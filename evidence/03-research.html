Cost is not the deciding factor. All nine come in below today’s $4,150/mo Heroku bill — the cheapest qualifying option is roughly a third of it. What actually narrows the field is pg_cron (removes Neon and Timescale outright), the 3,000-connection peak (removes Railway, and is the open question on Cloud SQL), and extension coverage that can’t be confirmed (removes PlanetScale for now).

Pick A · cheapest safe option

AWS RDS for PostgreSQL

$1,455/mo on-demand  ·  $1,010/mo with a 1-yr RI

WhyStock community Postgres, all three extensions on the supported list, 15 read replicas, every EU region, and the lowest-risk migration of the nine.

What it costs youYou own the parameter groups, the upgrades and the RDS Proxy config. It is a database, not a service — budget DBA time, not just dollars.

Pick B · least operational load

Crunchy Bridge

$2,160/mo with HA standby  ·  $1,120/mo without

WhySame Postgres, but pgBouncer is on by default, the extensions are pre-loaded (they maintain PostGIS upstream), you get a near-superuser role, and they run the migration with you.

What it costs you~48% more than RDS, a much smaller vendor, and one unverified claim sits on this option — see U3 below.

The choice between them is one question: do you want to spend the difference (~$700/mo) on not becoming a Postgres operations team? Everything else about these two is close enough to be noise.

3 claims I could not verify

These are gaps in the evidence, not opinions. Each one is scored pessimistically below, which means the ranking would change if any turns out to be favourable.

U1 PlanetScale for Postgres — is PostGIS available?

Their extensions page enumerates a supported set (pgvector, pg_stat_statements, uuid-ossp, citext, hstore, and others) and postgis is not on it — but the page never says the list is exhaustive, and the June 2026 changelog mentions “expanded extension support” without naming what was added. Asked in their community Slack on 2026-07-29; no answer as of writing.

If wrong: PlanetScale moves from ruled-out to viable, though pg_cron would still be unaccounted for.

U2 Cloud SQL — is managed connection pooling production-ready?

The managed connection pooling documentation was still labelled Preview when checked on 2026-07-31, with no GA date, and Google’s preview terms exclude previewed features from the Cloud SQL SLA. I found no statement that it is supported at 3,000 client connections. Scored as unavailable, which is why Cloud SQL’s migration rating assumes you run your own PgBouncer.

If wrong: Cloud SQL becomes the cheapest fully-qualifying option at ~$1,024/mo with a CUD — but the cross-cloud latency argument against it still stands.

U3 Crunchy Bridge — what is cross-region replica lag?

The docs describe cross-region read replicas but publish no lag figure and no RPO. A Crunchy sales engineer said “typically sub-second within Europe” on a call on 2026-07-30; that is not in any document and I could find no third-party benchmark. This is the one that matters most — it sits on a recommended option.

Do this before signing: if the plan depends on a second-region EU replica for read scaling, get the lag number in the contract.

Method & caveats

  • Prices are models, not quotes. Each is built from the vendor’s public list price at 16 vCPU / 64 GiB class compute, 400 GB of storage, and HA where the platform treats it as standard. Real bills will differ with IOPS, egress and support tier. Nobody was asked for a discount; assume 10–25% is negotiable at this size on RDS, Cloud SQL and Crunchy.
  • “Migration effort” is rated relative to a Heroku Postgres 16 origin, assuming logical replication from the existing follower and a short cutover window — not a dump/restore maintenance weekend.
  • EU residency here means “an EU region exists and data stays in it by default”. All nine vendors except Cloud SQL are US-incorporated, so a transfer impact assessment is needed regardless of where the bytes sit. That is a legal question, not one I answered.
  • Not evaluated: support responsiveness, actual incident history, and anything requiring a trial account. Two vendors (Crunchy, PlanetScale) would need a paid trial to test the extension set against your real schema — worth doing for whichever of the two picks you lean toward.
  • Source strength is labelled. DOCS and PRICING are vendor-published and dated. FORUM and CALL are weaker and are marked wherever they carry a claim.
