Horizontal overflow on the plan matrix

Where
section.plan-compare > table.plan-matrix
Fails
360 × 760 only. First failing width 379px; passes from 380px up.
Measured
viewport 360px · document.scrollWidth 380px → 20px of sideways scroll
Maths
348px table min-width + 2 × 16px padding-inline = 380px
Cause
New --halo-table-min: 348px applied to .plan-matrix; the old .plan-matrix--stacked modifier (card list ≤ 599px) was dropped during the markup rewrite.
Suggested fixRestore the stacked variant under @media (max-width:599px), or wrap the table in .scroll-x with overscroll-behavior-inline: contain so only the table scrolls, not the document.

Heading outline skips a level

Where
article.post-body h4.step-heading — 3 occurrences, all directly under h2#migrating-your-tokens
Fails
All three viewports (structural, not responsive)
Detected
axe-core 4.9 rule heading-order — 3 violations, impact moderate
Outline
h1 → h2 → h4 → h4 → h4 → h2
Rule
WCAG 2.2 1.3.1 Info and Relationships (Level A)
Cause
Steps were re-tagged h3 → h4 to inherit the new .step-heading size (18px/1.4) instead of applying the type token to an h3.
Suggested fixRevert the three headings to <h3 class="text-title-sm">. Size is identical — .text-title-sm and .step-heading both resolve to --halo-font-title-sm, so there is no visual change.

Finding 3
3

Label contrast fails WCAG AA

Where
form#contact-form label.field-label — 5 nodes: Full name, Work email, Company, Team size, Message
Fails
All three viewports
Now
#868B94 on #F4F5F7 = 3.10:1 at 14px/400 — needs 4.5:1
Was
#4B5160 on #FFFFFF = 7.94:1
Rule
WCAG 2.2 1.4.3 Contrast (Minimum), Level AA
Cause
--halo-text-subtle was tuned against --halo-surface-base (#FFF, 3.9:1 — already marginal) but the form sits on --halo-surface-raised (#F4F5F7).
Work emailbefore · 7.94:1 Work emailnow · 3.10:1 ✕ Work emailfix · 5.24:1 ✓
Suggested fixDarken the token to --halo-text-subtle:#5F6672 → 5.24:1 on #F4F5F7 and 6.5:1 on #FFF. Same token also feeds .form-hint and .table-caption — 9 further nodes clear AA for free.
